# 类比映射

## 机制

把陌生主题映射到一个容易独立理解的**结构保持**系统，使源系统的推理能迁移到目标系统。重点不是诗意相似，而是部分同构：对象间关系保持，即使对象本身不同。理论基础：结构映射理论（Gentner 1983）。

## 何时使用

- **可选** 讲解智能体——当 intent 提及 CS / 工程 / 数学背景时激活。
- **不要** 当无真正结构保持的类比——改用 `first_principles.md`。
- **不要** 在安全关键解释里——类比可能取代实际机制占据学习者心智。

## 输出形态

- **章节小标题**：`## 类比`
- 开头一句话命名**源**（可独立理解的系统）和**目标**（本主题）
- 短的**映射表**两列：源对象/关系 → 目标对象/关系
- 3-7 行；每行必须是结构对应，不是表面特征
- 一段短文说明**类比在哪里失效**——映射停止的承重点
- 总长 150-400 字

## 反模式

- **表面类比**：写"大脑像电脑"但不说明哪些关系对应
- **映射方向反了**：用更不熟悉的源解释更熟悉的目标
- **隐藏失效点**：略过类比失败的承重处——学习者会过度延伸

## 强制约束

- **全中文**：标题、术语全部中文。**禁止** "Analogy / Source / Target"。
- **禁止元对话**：直接给映射表与失效点，不说明类比来自用户背景或项目资料。

## 示例

```markdown
## 类比

源：版本控制系统（git）。目标：CRDT（无冲突复制数据类型）。

| git | CRDT |
|---|---|
| 提交 | 操作 |
| 分叉分歧 | 不同副本上的并发操作 |
| 人工合并解决 | 半格 join 的自动确定性合并 |
| rebase 重写历史 | 历史只追加 |

失效点：git 提交不可变，但**图**可被 rebase 重写；CRDT 操作不可变且图只追加。任何依赖历史重写的推理都不能迁移。
```

5 行结构映射、失效点明示。
