graph TD

  IMMUT -.->|互斥| MUT

  OWN -.不直接相关.-> SAFE[Unsafe Rust]
  MUT -->|封装| CELL[RefCell/Cell]
  IMMUT -->|多所有者| RC[Rc/Arc]

高阶问题（不给答案，自己想）

1. 如果 Rust 没有"移动语义"，会发生什么？ 反事实
假设 Rust 像 Python 一样，let s2 = s1; 之后 s1 还能用。会破坏哪些保证？
提示：想想"双重释放"和"alias + mutation"。
2. 为什么 &mut T 不能同时存在两个，但 &T 可以有多个？ 设计哲学
从内存安全的角度，区分"读"和"写"的本质是什么？
提示：想想"读者-写者问题"和数据竞争。
3. RefCell<T> 怎么"绕过"借用规则的？ 内部可变性
编译期检查 vs 运行时检查的取舍是什么？为什么需要这种东西？
提示：思考"我需要在不可变接口里修改数据"的真实场景。
4. 'static 是"程序运行到结束"的意思吗？ 误解检查
它和"全局变量"是同一个东西吗？为什么 String 是 'static？
5. Rust 的所有权能完全替代 GC 吗？ 边界思考
有没有 GC 能做但 Rust 做不到的？循环引用怎么办？
提示：Rc + RefCell + 循环 = 什么后果？
