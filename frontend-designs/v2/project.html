Rust 所有权模型

所有权是 Rust 最独特和强大的特性。它使 Rust 能在不使用垃圾回收器的情况下做出内存安全保证，同时拥有 C++ 级别的性能和高级语言的安全性。

三条规则

  1. 每个值有且仅有一个所有者 — 一个负责其内存的变量。
  2. 同一时刻只能有一个所有者 — 赋值给另一个变量时，原变量失效（这叫做移动）。
  3. 所有者离开作用域 → 值被丢弃 — 内存自动释放，无需 GC。

移动语义

在 Rust 中，赋值移动所有权而非复制数据：

let s1 = String::from("hello");
let s2 = s1; // s1 被移动到 s2

// println!("{}", s1); // 错误：移动后借用
println!("{}", s2);    // 正确：s2 拥有数据

这与浅拷贝语言有本质区别。移动之后，s1 不再有效——编译器在编译期强制执行这一点。

借用与引用

引用让你在不获取所有权的情况下借用一个值：

fn calculate_length(s: &String) -> usize {
    s.len() // 借用 s，不获取所有权
}

let s = String::from("hello");
let len = calculate_length(&s);
// s 在这里仍然有效！

可变引用

你可以修改借用的数据，但有一个关键限制：

fn add_world(s: &mut String) {
    s.push_str(", world");
}
核心限制：在特定作用域中，同一份数据只能有一个可变引用。这可以在编译期就防止数据竞争。

生命周期

生命周期是 Rust 确保引用始终有效的方式：

fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}

'a 标注告诉编译器：返回的引用的存活时间至少为两个输入生命周期中较短的那个。这在编译期验证。

总结表

概念规则检查时机
所有权每个值一个所有者编译期
移动赋值转移所有权编译期
借用引用但不拥有编译期
生命周期引用必须始终有效编译期

常见误解

  • Rust 不使用垃圾回收器——所有清理都是确定性的。
  • 借用不是复制——不会复制任何数据。
  • 生命周期很少需要显式标注——编译器能推断大部分。
