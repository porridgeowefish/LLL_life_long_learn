# MECE 拆解

## 机制

把主题拆成**相互独立、完全穷尽**的子概念。让学习者一眼看到主题全貌，并立即识别 20% 决定 80% 理解的关键驱动（帕累托）。理论基础：Barbara Minto《金字塔原理》+ 帕累托分布。

## 何时使用

- **必选** 讲解智能体的"MECE 拆解"章节。
- **可选** 练习智能体拆解题型。
- **不要** 用于纯定义性主题（如"什么是 git"）——改用 `boundary_map.md`。
- **不要** 当主题只有一个天然轴时——改用 `concept_graph.md`。

## 输出形态

- **章节小标题**：`## MECE 拆解`
- 开头一句话明确**拆解维度**（如"按生命周期阶段拆解"、"按结构层拆解"）
- 树形结构（嵌套列表），**最多 3 层**
- 每个叶节点 1-2 句话说明它是什么、为什么重要
- 用 ⭐ 标关键驱动叶节点（约 20%）
- 总长 200-500 字

## 反模式

- **维度混合**：拆解到一半从"按时间"切换到"按功能"——破坏 MECE
- **超过 3 层**：学习者失焦——折叠或拆分
- **不标 ⭐**：每个叶节点看起来一样重要——学习者不知道投入哪

## 强制约束

- **全中文**：标题、术语、解释全部中文。**禁止** "MECE Decomposition / Topic Definition" 等。
- **禁止元对话**：直接给拆解，不要解释"以下拆解基于..."。

## 示例

```markdown
## MECE 拆解

按结构层（从前到后）拆解。

- 前端层
  - 渲染管线 ⭐
  - 状态存储
- 服务层
  - 认证边界 ⭐
  - 业务处理器
- 存储层
  - 写路径 ⭐
  - 复制机制
```

3 层、3 个 ⭐（生产里最容易出问题的部分）、每个叶节点不超过 1 句说明。
